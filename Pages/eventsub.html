What is Twitch EventSub?

EventSub is Twitch’s official event delivery system. Instead of repeatedly calling endpoints (polling), Twitch pushes notifications whenever an event occurs on a channel: a follow, a subscription, a raid, a poll update, a Channel Points redemption, and more.

For interactive games and “Twitch Plays”-style experiences, EventSub is the foundation for audience-driven gameplay: chat triggers effects, votes decide outcomes, monetization events unlock content, and stream milestones can change the world in real time.

How StreamSync uses EventSub

Subscriptions management

StreamSync creates and deletes EventSub subscriptions for the types you select, and queues requests to avoid spamming Helix. It also builds the correct condition fields per event type (broadcaster, moderator, raid target, etc.).

Two transport modes

The component supports both WebSocket transport and an optional local webhook server. If webhook isn’t available on a build target, StreamSync falls back to WebSocket automatically.

Blueprint-friendly events

EventSub payloads are dispatched as Blueprint multicast events with raw JSON, and you can use parse helpers to turn them into typed structs for gameplay logic.

Transport & security

Transport selection: Webhook or WebSocket

  • Webhook: StreamSync can run a local HTTP server and expose a public callback URL (when enabled).
  • WebSocket: StreamSync uses a Twitch EventSub WebSocket session_id as transport.
  • Fallback: if webhook can’t start, it falls back to WebSocket.

StreamSync builds the EventSub subscription JSON with a transport block that switches between webhook and websocket.

Scope validation before subscribing

For event types that require permissions, StreamSync checks the user token scopes before queuing the subscription. That means missing scopes are caught early, instead of failing silently later.

You’ll find the exact mapping in the Required OAuth scopes table below.

Parsing & dispatch (raw JSON → typed structs)

Dispatch: EventSub type → Blueprint event

StreamSync exposes an Event Library that routes (Type, Json) into the correct Blueprint multicast event (PollBegin, PredictionProgress, Follow, Raid, Subscribe, Cheer, Hype Train, etc.).

This lets you keep a single “EventSub Received” entry point and then dispatch cleanly by type.

Parse helpers: gameplay-ready data

The Parse Library provides functions/structs that turn EventSub JSON into typed data for your game logic (poll choices & tallies, prediction outcomes, follow metadata, raid viewers, subscription tier, and more).

Goal: you should rarely need to manually JSON-walk in Blueprints.

Why parsing matters for Unreal Engine projects

Raw EventSub payloads are great for debugging, but in production you want stable, explicit fields: IDs, timestamps, vote tallies, user display names, amounts and tiers. Typed parsing makes your gameplay logic simpler and safer.

For other types (subs, cheers, bans, stream online/offline, etc.), StreamSync can subscribe using the broadcaster condition without enforcing a required scope in the validation map above.

Setup checklist (recommended)

  1. Authenticate with Twitch and obtain a user token containing the scopes you need.
  2. Enable EventSub on the StreamSync component and choose your event selection (Channel Points / Polls / Predictions / etc.).
  3. Pick transport: WebSocket for easiest setup, or webhook if you want a callback URL and secret verification.
  4. Bind Blueprint events (Follow, Raid, Channel Points redemption, Poll events, Prediction events…).
  5. Use Parse Helpers to convert raw JSON into typed structs for clean gameplay logic.

Best practice: don’t build gameplay on raw JSON strings

Use the parsing layer whenever possible. It reduces errors, avoids field name typos, and keeps your Blueprints clean.
